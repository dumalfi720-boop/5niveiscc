⚙ Claude Code: o motor

Os 8 elementos centrais de quem trabalha com Claude Code todos os dias.

O que é:

Claude Code roda como CLI no terminal ou como aba Code no Claude Desktop. Mesmo engine, interface diferente. Terminal é mais rápido depois que acostuma.

Por que aprender:

Não precisa ser dev terminal-fluente — comece pela aba Code, evolua quando quiser velocidade.

Conceitos-chave:

CLI · Desktop · Mesmo modelo · Mesmas features · Curva de aprendizado opcional.

O que é:

Markdown na raiz do projeto. Claude lê em toda conversa: stack, convenções, papel, regras. Regra de ouro: ≤200 linhas. Use @arquivo pra detalhes só quando precisar.

Por que aprender:

É o que separa N4 de N3. Sem isso, Claude reinventa convenções a cada sessão.

Conceitos-chave:

Stack · Convenções · Papel · Regras · @ pra detalhes · Atualize quando errar.

O que é:

Quando Claude erra, diga "atualize o claude.md pra não fazer isso de novo". A própria Anthropic faz isso. Em semanas, o arquivo treina Claude no seu jeito.

Por que aprender:

É o loop que separa N4 médio de N4 dominante.

Conceitos-chave:

Erro = oportunidade · Regra escrita > regra falada · Versão controlada · Compartilhe no time.

O que é:

Shift+Tab 2x ativa plan mode: Claude lê o código, apresenta plano, espera sua aprovação. Opus Plan: Opus planeja, Sonnet executa. Custo metade, qualidade igual.

Por que aprender:

Aprovar plano explícito reduz refactors. Opus Plan é o atalho de custo mais subestimado.

Conceitos-chave:

Plano antes do código · Aprovação humana · Opus pra planejar · Sonnet pra executar.

O que é:

Claudes especializados pra trabalhos específicos: um pra testes, um pra segurança, um pra docs. Cada um roda em contexto próprio — ruído de um não polui o outro.

Por que aprender:

Você monta um "time de engenharia" com especialistas. Múltiplos em paralelo.

Conceitos-chave:

Context isolado · Especialista por papel · Comunicação via main session · Não conversam diretamente.

O que é:

claude-worktree feature-name cria workspace git isolado por branch. Abre outro terminal e roda outro. 3-4 sessões paralelas sem conflito de arquivos.

Por que aprender:

É como Boris Cherny (criador do Claude Code) trabalha: 5 sessões mínimo todo dia.

Conceitos-chave:

Isolated git workspace · Branch própria · Sem conflito · Sweet spot 3-4.

O que é:

Model Context Protocol conecta ferramentas externas. Mas a regra (da própria Anthropic) é: CLI primeiro, endpoints REST depois, skills em seguida, MCP só quando nada mais cabe. CLI gasta 60-70% menos tokens.

Por que aprender:

Quem ignora essa hierarquia paga 3x mais em tokens e perde contexto rápido.

Conceitos-chave:

CLI tools (gh, aws, gcloud) · APIs REST · Skills · MCP último.

O que é:

Feature de Janeiro/2026: quando MCP passa de 10% do contexto, Claude defere carregamento de tools até precisar. Reduz overhead em 85%, zero config.

Por que aprender:

Quem usa MCP precisa entender isso — é a feature que torna MCP viável em sessões longas.

Conceitos-chave:

10% trigger · Tool search automático · Carregamento sob demanda · Mais MCP sem pagar contexto.

🚀 Movimentos de alto impacto

Os 8 hábitos que distinguem usuário casual de power-user.

O que é:

/compact resume o histórico antigo em um sumário tight (rode proativamente, não espere o warning). /context mostra onde seus tokens estão indo. Combinado com prompt caching: -60-90% de custo em sessões longas.

Por que aprender:

Janela de 1M no Opus 4.7 ainda fica sloppy depois de 50%. Quem controla, paga menos e mantém qualidade.

Conceitos-chave:

/compact proativo · /context pra debug · Prompt caching automático · 50% é o gatilho.

O que é:

Shift+Tab cicla pro auto mode: comandos seguros passam por classifier em vez de pedir aprovação. /focus oculta intermediários, mostra só resultado final.

Por que aprender:

Parar de apertar "yes" 30x por sessão libera você pra rodar paralelo de verdade.

Conceitos-chave:

Auto mode · Classifier de segurança · /focus · Switch entre sessões.

O que é:

Boris Cherny diz que esse é o hábito mais importante do N4: dê a Claude jeito de checar o próprio trabalho (extensão Chrome pra abrir browser, screenshot, rodar testes) e itere até PASS.

Por que aprender:

Boris diz que dobra ou triplica a qualidade do output.

Conceitos-chave:

Self-test · Chrome extension · Screenshots · Não me chame antes de PASS.

O que é:

Se você digitou o mesmo prompt duas vezes, transforme em slash command. Boris usa /commit-push-pr dezenas de vezes por dia. Vivem em .claude/commands/.

Por que aprender:

Cada slash é uma macro pessoal. Multiplique por 20 — sua produtividade explode.

Conceitos-chave:

.claude/commands/ · Compartilhável com time · Versionado em git · /commit-push-pr clássico.

O que é:

/rewind (ou Esc Esc) descarta tentativa falha sem poluir contexto. /btw deixa você fazer pergunta paralela sem quebrar o fluxo. /branch (antigo /fork) bifurca a conversa pra testar caminhos diferentes.

Por que aprender:

São "controle de versão" do raciocínio. Pareia perfeitamente com worktrees.

Conceitos-chave:

Rewind = limpar fracasso · BTW = dúvida lateral · Branch = experimento.

O que é:

Lê seu último mês de uso e gera relatório: padrões repetitivos, gastos de tokens, prompts candidatos a virar skill, regras pra adicionar no claude.md.

Por que aprender:

Maioria não tem dado do próprio uso. Roda 1x/mês, vira mapa de melhoria.

Conceitos-chave:

Audit pessoal · Padrões · Candidatos a skill · Regras de claude.md emergem.

O que é:

/output style new troca a "personalidade" do Claude Code. Built-ins: default, explanatory, learning. Custom: code reviewer mode, no-fluff, documentation writer.

Por que aprender:

Mesma ferramenta cobre 10 papeis diferentes sem misturar.

Conceitos-chave:

Built-in vs custom · Por projeto · Style trocável a quente.

O que é:

PRs N4 trazem: contexto do problema, plano executado, arquivos alterados com motivo, evidência de testes/checks, riscos conhecidos. Padrão de PR é parte do claude.md.

Por que aprender:

PR bom é diferença entre cliente que paga R$ 25k e cliente que vira recorrente.

Conceitos-chave:

Template de PR no claude.md · Evidência de teste · Riscos listados · Revisão por subagente.

🚀 Cheat Code: parar de babar Claude

A passagem do N4 pro N5 é mental, não técnica.

O que é:

A maioria no N4 vira babá: dispara sessões e fica olhando cada uma. Identifique 3 tarefas que você faz manualmente embora poderiam ser slash command, skill ou hook.

Por que aprender:

Babá é o gargalo. Sai do gargalo = sobe pro N5.

Conceitos-chave:

Auditar 1 semana · 3 tarefas-babá · Cada uma vira automação.

O que é:

Tarefa repetitiva: slash command. Workflow complexo: skill. Validação automática em momento específico: hook (pré-N5). Cada uma das 3 tarefas-babá vira um desses.

Por que aprender:

Escolher a abstração certa = manutenção fácil.

Conceitos-chave:

Slash = atalho · Skill = workflow · Hook = trigger automático.

O que é:

Gerenciar paralelo na unha · não usar plan mode · pular verificação · claude.md gigante · ignorar /insights · MCP-first em vez de CLI-first.

Por que aprender:

Cada erro é um teto invisível. Cair em 2-3 deles = você ficou 1 ano sem evoluir.

Conceitos-chave:

Gerenciamento ≠ babá · Plan mode default · Verificação obrigatória · CLI antes de MCP.

O que é:

Você sente "isso podia rodar todo dia 8h sem eu precisar abrir o laptop". É o teto do N4 — entra o N5 (rotinas em nuvem).

Por que aprender:

Reconhecer evita "espremer N4" e demorar pra subir.

Conceitos-chave:

Rotina vs sessão · Sem máquina · 24/7 · Sleep-friendly.

O que é:

N4 entrega sistemas reais — não automação isolada. Cobre por valor: o cliente paga R$ 50k porque a feature destrava R$ 500k/ano em receita ou poupa 2000h de equipe.

Por que aprender:

É onde freelance vira agência sustentável.

Conceitos-chave:

ROI explícito · Escopo fechado · Manutenção mensal · Cliente que entende valor.

O que é:

Antes de habilitar N5: escolha 1 rotina baixíssimo risco (resumo diário que só vem pra você). Roda manual 5x. Se passar nas 5, agenda. Confiança se constrói, não se assume.

Por que aprender:

Pular essa etapa = automação que destrói confiança no 1º bug.

Conceitos-chave:

Baixo risco primeiro · Manual antes de cron · 5 rodadas mínimo · Só você como destinatário.
