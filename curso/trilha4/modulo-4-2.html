MÓDULO 4.2 · ~30 min

🚀 Movimentos de alto impacto

Os 8 hábitos que separam usuário casual de power-user. Quem domina os 8 cobra R$ 25k+ por projeto com tranquilidade.

1

📐 Master do context window

Janela de 1M no Opus 4.7 ainda fica "sloppy" depois de 50% de uso. Dois comandos resolvem:

  • • /compact — resume o histórico antigo em sumário tight. Rode proativamente, não quando aparecer o warning (já é tarde).
  • • /context — mostra onde seus tokens estão. Identifica vilões: file longo, MCP overhead, histórico inflado.

Combinado com prompt caching (automático no Claude Code): redução de 60-90% em sessões longas.

2

⚡ Auto mode + /focus

Auto mode: Shift+Tab cicla entre manual/auto. Em auto, comandos seguros passam por classifier interno em vez de pedir "yes" a cada passo. /focus: oculta os passos intermediários, mostra só o resultado final.

Os 2 juntos: você dispara uma sessão, troca pra outra worktree, volta quando ela termina. É exatamente como Boris roda 5 paralelas todo dia.

3

🔍 Loop de verificação — Claude testa o próprio trabalho

Boris Cherny diz: "é o hábito mais importante do N4." Dê a Claude jeito de checar o que entrega:

  • • Pareie Claude Code com extensão Chrome — ele abre o browser, testa a UI, itera
  • • Peça screenshots da feature funcionando
  • • "Não me chame até os testes passarem"
  • • Defina critério de sucesso explícito antes de começar

Boris diz que esse hábito sozinho 2-3x a qualidade do output.

4

⌨ Slash commands customizados

Se você digitou o mesmo prompt 2x, vire slash command. Vivem em .claude/commands/:

.claude/commands/commit-push-pr.md:

Roda os testes. Se passarem:
1. git add .
2. git commit com mensagem usando convenção do projeto
3. git push -u origin HEAD
4. gh pr create com template padrão
5. Cole o link da PR

Boris usa /commit-push-pr dezenas de vezes/dia. Comandos podem ser compartilhados (versionados em git) com o time inteiro.

5

🔄 /rewind, /btw, /branch — git pra conversa

/rewind (ou Esc Esc) — descarta tentativa falha completamente, sem deixar correções poluindo o contexto. Volta pra uma mensagem anterior limpa.
/btw — faz pergunta paralela ("o que essa função faz mesmo?") sem quebrar o fluxo principal.
/branch — bifurca conversa em ponto exato. Testa caminho A, volta, testa B. É git pra raciocínio. Pareia perfeitamente com worktrees: um pra arquivos, outro pra pensamento.
6

📊 /insights — relatório mensal do seu uso

Comando subestimado: lê seu último mês e gera relatório com padrões, gastos de tokens, prompts que você repetiu e regras candidatas a entrar no claude.md.

Rode 1x/mês. Vira mapa de melhoria personalizado. Você descobre: "eu reescrevi essa instrução 12 vezes em 4 semanas — deveria ser skill".

7

🎭 Output styles — 10 jobs com mesmo Claude

/output-style new cria personalidade nova. Built-ins: default, explanatory, learning. Custom comum: code reviewer mode, no-fluff, docs writer, juniors-friendly.

Mesma ferramenta cobre 10 papéis diferentes sem misturar. Útil quando o mesmo projeto pede saídas formatadas pra audiências distintas.

8

🔀 PRs melhores e revisão sistemática

PR N4 carrega: contexto do problema, plano executado, arquivos alterados com motivo, evidência de testes, riscos conhecidos. Esse padrão deve estar no claude.md.

Use subagente "code-reviewer" pra revisão automática antes de pedir review humano. Resultado: PR já chega com auto-crítica e principais issues mitigadas.

É o que separa "Claude Code fez código" de "Claude Code fez engenharia". Cliente premium vê e paga.
