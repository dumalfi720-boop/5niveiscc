MODULE 5.2 · ~30 min

🛡 Operating autonomously responsibly

The N5's lock is confidence, not technique. This module teaches you how to build confidence gradually — just like you learned to drive.

1

💰 Task budgets (Opus 4.7 beta)

You define the total token budget for the entire routine — thinking, tools, output are included in the chapter. The model sees the budget and regulates itself, ending gracefully when it sees that it is going to run out.

It is the most underrated lever for cost control in self-employed. Without it, agents "travel" and burn accounts. Currently API only — but will come to Code and co-work.

2

👥 Agent teams (experimental)

Multiple Claudes coordinated by "lead" agent. Different from subagents (N4): here they message, have a shared channel, debate, have a common task list.

Use it when you see that you have a spare token budget — agent teams spend a lot. Spin up, ask them to debate a decision, choose the best argument.

Protocols:MCP for tools (we've already seen), Ato for agent-to-agent (new, Anthropic+Google standard from 2025).

3

✅ Outcomes — automatic multi-agent validation

Feature 2026: you defineexplicit outcome(success = X, Y, Z). A validator agent checks it before the delivery reaches you. If it fails, it triggers a new iteration.

Kill "Claude delivered it but it's not good". Confidence builds with repeated automatic PASS.

4

📅 7-day plan — gradual confidence

  • Day 1:choose a very low-risk routine (summary just for you).
  • Day 2:define scope — sources, format, success criteria.
  • Day 3:create optimal output format.
  • Day 4:add notification (Slack, email) with link to output.
  • Day 5:rotate manual 3-5 times. Refine.
  • Day 6:schedule on a routine basis, with supervision (you review each output).
  • Day 7:review logs. If all 7 runs were good, let it run alone. Otherwise, 5 more days.
5

🎯 3 complete ready-made examples

Automatic PR Review

Trigger:GitHub event "PR open"
Flow:Claude reads diff → runs tests → analyzes logic → posts inline comments → summarizes on Slack #dev
Security:Read-only in the repo. Don't merge. Do not comment with a rude tone. It doesn't block anyone.

Pre-meeting briefing

Trigger:Calendar event starts at 1h
Flow:Identifies participants → Notion/Slack history search → summarizes context + pending issues + key questions → sends email
Security:Only read authorized sources. Does not respond to emails for you.

Standalone weekly report

Trigger:Cron Friday 5pm
Flow:Reads GitHub (PRs/issues), Notion (decisions), Slack (#general) → composes markdown with 3 parts (done, in progress, risks) → delivers to the #weekly channel
Security:It does not cite confidential decisions. It does not attribute failure to a specific person.

6

📋 Security checklist

  • ☐ Structured logs— each execution records: input, tools used, output, tokens.
  • ☐ Parallel dry-runfor 1 week — routine runs in "simulation" mode before the real one.
  • ☐ kill switchaccessible — command or button to pause.
  • ☐ Explicit jurisdiction— "up to R$X / quantity Y, execute; above, ask for human approval".
  • ☐ Read-only by default— write only where necessary.
  • ☐ Token budget— strict cap.
  • ☐ Failure alert— any error will be sent to you immediately.
7

🪜 Trust ladder: N4→N5 is psychological

Almost everyone in N4 can technically build a routine. But it doesn't enable. The lock is trust in a system that runs while you sleep.

Fix is ​​the same as learning to drive: empty parking lot first. Very low risk routine, just for you, 10 perfect runs = first confidence. Plus 100 = second. Don't jump.

8

⚖ Deterministic vs non-deterministic

Deterministic automation (classic ETL, “if X then Y”) = input → fixed output. Reliable.

Claude skills/agents = non-deterministic. More powerful, but require validation. Mix the two: deterministic ETL carries over, LLM in between only where creative judgment is needed.

Non-deterministic without validator = recipe for disaster. Automatic outcomes do the trick.
