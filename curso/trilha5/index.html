5.1~35 min

🛰 Claude as infrastructure

The 8 elements that take Claude away from the “laptop on” and put him to work 24/7.

What is it:

Saved Claude Code settings that run on Anthropic's infrastructure. Your laptop turns off. Triggers: cron, API call, GitHub event.

Why learn:

It is the qualitative leap of the N5. Everything in the course points to this.

Key concepts:

/schedule cloud · Miscellaneous triggers · No machine · Anthropic infrastructure.

What is it:

Routines are triggered by: (1) cron — "every day 8am", (2) API call — webhook arrives, triggers, (3) GitHub event — PR opened, triggers review.

Why learn:

Right triggers = useful automation. Wrong triggers = noise or loop.

Key concepts:

Cron for routine · API for integration · Webhook for event · Idempotence.

What is it:

Custom logic that triggers at moments in the life cycle: pre-tool-use (blocks rm -rf before executing), post-edit (formats all modified files), stop (Slack ping at the end of a long session), response (notification for each response).

Why learn:

They are what separates "cool demo" from "reliable production system".

Key concepts:

18+ hook types · Do not consume context until triggered · Red squigglies for agent.

What is it:

Control sessions outside the terminal. Two flavors: 1-way (external event triggers Claude — calendar sets call, Claude prepares briefing) and 2-way (you text Claude from your cell phone, he operates on your codebase).

Why learn:

Without channels, N5 is stuck to the terminal. With channels, it becomes an “always on” infrastructure.

Key concepts:

1-way vs 2-way · Human-Claude pairs · Smart notifications · Custom webhook.

What is it:

Claude Code runs without human session:claude -p "faz X"returns the output. You channel to Slack, Datadog, another agent — free pipeline.

Why learn:

This is what makes Claude viable as a part of larger systems.

Key concepts:

No TTY · stdin/stdout · Pipe-friendly · Composable.

What is it:

Python and TypeScript libraries to build your own product based on the Claude Code engine.

Why learn:

You stop being a user and become an AI supplier to third parties. Exit to SaaS product.

Key concepts:

Official SDK · Streaming · Customized tools · Embed in own app.

What is it:

/remote-controlconnects local session to Claude's mobile app. QR or link. You walk down the street, send commands from your cell phone, the session continues running on your machine.

Why learn:

Work stopped having a “place”. You operate engineering remotely from your iPhone.

Key concepts:

QR pairing · Push notifications · Local session maintained · Mobile-first.

What is it:

Sub-agent in the background that "maintains" memory between sessions: deletes contradictory facts, merges duplicates, converts "yesterday" to real dates. As a human who dreams to consolidate memory.

Why learn:

Without it, memory drifts. With this, Claude stays sharp even after 6 months.

Key concepts:

Background agent · Merge of duplicates · Resolution of contradiction · You have to activate manually.

5.2~30 min

🛡 Operating autonomously responsibly

The lock of the N5 is trust. This module teaches you how to build confidence gradually.

What is it:

You define the token budget for the entire routine — thinking + tools + output are included in the chapter. Claude regulates himself and ends gracefully when he sees that he is about to explode.

Why learn:

Without this, freelancers can "travel" and burn accounts. With this, you can really cover it.

Key concepts:

Token cap · Self-regulation · API only (for now) · Critical cost lever.

What is it:

Multiple Claudes coordinated by a "lead". Different from subagents (N4): here they message each other, have a shared channel, debate, shared task list.

Why learn:

It's the next frontier: Claude teams that decide together. Still experimental, but those who understand early capitalize.

Key concepts:

Lead agent · Channel · Debate · MCP (tool) + Ato (agent-to-agent).

What is it:

Anthropic Feature 2026: explicit outcome + automatic validator. You define "success = X, Y, Z" and a review agent checks it before the delivery reaches you.

Why learn:

Kill "Claude delivered it but it's not good". Trust builds with automatic PASS.

Key concepts:

Outcome = success · Agent validator · Pass/fail · Iterate until PASS.

What is it:

Day 1: choose simple routine · Day 2: define scope · Day 3: create output format · Day 4: add notification · Day 5: manual wheel · Day 6: schedule with supervision · Day 7: review logs.

Why learn:

Skipping this plan = automation that destroys trust at the first bug.

Key concepts:

1 routine at a time · Manual before cron · Mandatory logs · Daily iteration.

What is it:

(1) Automatic PR review: GitHub event → review + inline comments + Slack · (2) Pre-meeting briefing: calendar event → context reading → 1-page email · (3) Weekly report: cron Friday 5pm → source reading → delivery.

Why learn:

These are the 3 anchor cases of N5. Master the 3, see all the others as variations.

Key concepts:

Trigger + action + delivery · Does not block merge · Read-only is the default · Notifies human.

What is it:

Before enabling any routine: log of each execution · dry-run that runs in parallel for 1 week · accessible kill switch · authority (up to R$/X amount, Claude executes alone; above, requests human approval).

Why learn:

Without these 4, autonomy becomes a risk.

Key concepts:

Structured logs · Parallel dry-run · Kill switch · Explicit scope.

What is it:

Almost everyone can create a technical routine. But it doesn't enable. Reason: trusting a system running while you sleep is unnatural. The fix is ​​the same as learning to drive: start in an empty parking lot.

Why learn:

Recognizing that the lock is psychological frees you from "expecting more features".

Key concepts:

Confidence = exposure · Low repeated risk · 10 perfect runs = first confidence · 100 runs = second.

What is it:

Deterministic automations (move file X to folder Y) are safe — input → fixed output. Claude skills/agents are more powerful non-deterministic but require more validation.

Why learn:

Total trust in something non-deterministic is a recipe for disaster. Mix the two.

Key concepts:

Deterministic ETL · LLM in the middle only where you need it · Clear limits · Auditable outputs.

Key concepts:

Official Anthropic · Community · Plugins (bundles) · Marketplace by verticals.

What is it:

Why learn:

Whoever mines first delivers the customer in 1 week instead of 1 month.

Key concepts:

Search-first · Validate author · Fork before adapting · Contribute back.

What is it:

Fork · adapt to context · keep changelog clear · document customizations · contribute patches back when it makes sense.

Why learn:

Without discipline, you'll be stuck with the old version and miss out on upstream updates.

Key concepts:

Clear fork · Documented diff · Periodic rebase · Contribute back.

What is it:

Why learn:

N5 isn't "selling AI agent" — it's "selling SLA, time reduction, reliable infrastructure."

Key concepts:

Measurable SLA · Recurring revenue · Setup + maintenance · Positioning as infrastructure.

What is it:

Enable routine without dry-run · sell autonomy in creative task · do not monitor logs · promise SLA without authority · ignore token costs · deliver without runbook.

Why learn:

Each of these turns a customer into a former customer.

Key concepts:

Always dry-run · No creative self-write · Visible logs · Clear scope · Token budget · Mandatory runbook.

What is it:
