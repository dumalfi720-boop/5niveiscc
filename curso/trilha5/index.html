🛰 Claude como infraestrutura

Os 8 elementos que tiram Claude do "laptop ligado" e o colocam pra rodar 24/7.

O que é:

Configurações de Claude Code salvas que rodam na infra da Anthropic. Seu laptop fica desligado. Triggers: cron, API call, GitHub event.

Por que aprender:

É O salto qualitativo do N5. Tudo no curso aponta pra isso.

Conceitos-chave:

/schedule cloud · Triggers diversos · Sem máquina · Anthropic infra.

O que é:

Routines acionam por: (1) cron — "todo dia 8h", (2) API call — webhook chega, dispara, (3) GitHub event — PR aberto, dispara revisão.

Por que aprender:

Triggers certos = automação útil. Triggers errados = ruído ou loop.

Conceitos-chave:

Cron pra rotina · API pra integração · Webhook pra evento · Idempotência.

O que é:

Lógica custom que dispara em momentos do ciclo de vida: pre-tool-use (bloqueia rm -rf antes de executar), post-edit (formata todo arquivo modificado), stop (Slack ping ao fim de sessão longa), response (notificação a cada resposta).

Por que aprender:

São o que separa "demo legal" de "sistema de produção confiável".

Conceitos-chave:

18+ tipos de hook · Não consomem contexto até disparar · Red squigglies pra agente.

O que é:

Controle sessões fora do terminal. Dois sabores: 1-way (evento externo dispara Claude — calendário marca call, Claude prepara briefing) e 2-way (você texta Claude do celular, ele opera no seu codebase).

Por que aprender:

Sem channels, N5 fica preso ao terminal. Com channels, vira infraestrutura "sempre ligada".

Conceitos-chave:

1-way vs 2-way · Pares humano-Claude · Notificações inteligentes · Webhook custom.

O que é:

Claude Code roda sem sessão humana: claude -p "faz X" retorna a saída. Você canaliza pra Slack, Datadog, outro agente — pipeline livre.

Por que aprender:

É o que viabiliza Claude como peça em sistemas maiores.

Conceitos-chave:

Sem TTY · stdin/stdout · Pipe-friendly · Componível.

O que é:

Bibliotecas Python e TypeScript pra construir seu próprio produto em cima do engine do Claude Code.

Por que aprender:

Você para de ser user e vira fornecedor de IA pra terceiros. Saída pra produto SaaS.

Conceitos-chave:

SDK oficial · Streaming · Tools customizadas · Embed em app próprio.

O que é:

/remote-control conecta sessão local à app mobile do Claude. QR ou link. Você anda na rua, manda comandos do celular, sessão segue rodando na sua máquina.

Por que aprender:

Trabalho parou de ter "lugar". Você opera engineering remotamente do iPhone.

Conceitos-chave:

QR pairing · Push notifications · Sessão local mantida · Mobile-first.

O que é:

Subagente em background que faz "manutenção" da memória entre sessões: apaga fatos contraditos, mescla duplicados, converte "ontem" pra datas reais. Como humano que sonha pra consolidar memória.

Por que aprender:

Sem isso, memória drifta. Com isso, Claude fica afiado mesmo após 6 meses.

Conceitos-chave:

Background agent · Merge de duplicados · Resolução de contradição · Tem que ativar manualmente.

🛡 Operando autônomos com responsabilidade

A trava do N5 é confiança. Esse módulo te ensina a construir confiança gradualmente.

O que é:

Você define orçamento de tokens pra rotina inteira — thinking + tools + output entram no cap. Claude se auto-regula e encerra graciosamente quando vê que vai estourar.

Por que aprender:

Sem isso, autônomos podem "viajar" e queimar conta. Com isso, dá pra capar de verdade.

Conceitos-chave:

Token cap · Auto-regulação · API only (por enquanto) · Lever de custo crítico.

O que é:

Múltiplos Claudes coordenados por um "lead". Diferente de subagentes (N4): aqui eles se mensagem, têm channel compartilhado, debate, task list compartilhada.

Por que aprender:

É a próxima fronteira: equipes de Claude que decidem juntas. Ainda experimental, mas quem entende cedo capitaliza.

Conceitos-chave:

Lead agent · Channel · Debate · MCP (tool) + Ato (agent-to-agent).

O que é:

Feature 2026 da Anthropic: outcome explícito + validador automático. Você define "sucesso = X, Y, Z" e um agente revisor checa antes da entrega chegar em você.

Por que aprender:

Mata o "Claude entregou mas não está bom". Confiança constrói com PASS automático.

Conceitos-chave:

Outcome = sucesso · Validador agente · Pass/fail · Iterar até PASS.

O que é:

Dia 1: escolha rotina simples · Dia 2: define escopo · Dia 3: cria formato de saída · Dia 4: adiciona notificação · Dia 5: roda manual · Dia 6: agenda com supervisão · Dia 7: revisa logs.

Por que aprender:

Pular esse plano = automação que destrói confiança no primeiro bug.

Conceitos-chave:

1 rotina por vez · Manual antes de cron · Logs obrigatórios · Iteração diária.

O que é:

(1) Revisão automática de PR: GitHub event → revisão + comments inline + Slack · (2) Briefing pré-reunião: calendar event → leitura de contexto → e-mail com 1 página · (3) Relatório semanal: cron sexta 17h → leitura de fontes → entrega.

Por que aprender:

São os 3 casos âncora do N5. Domina os 3, vê todos os outros como variações.

Conceitos-chave:

Trigger + ação + entrega · Não bloqueia merge · Read-only é o default · Notifica humano.

O que é:

Antes de habilitar qualquer rotina: log de cada execução · dry-run que rode em paralelo por 1 semana · kill switch acessível · alçada (até R$/quantidade X, Claude executa sozinho; acima, pede aprovação humana).

Por que aprender:

Sem essas 4, autonomia vira risco.

Conceitos-chave:

Logs estruturados · Dry-run paralelo · Kill switch · Alçada explícita.

O que é:

Quase todo mundo consegue criar rotina técnica. Mas não habilita. Razão: confiar em sistema rodando enquanto você dorme é antinatural. A fix é igual a aprender a dirigir: comece num estacionamento vazio.

Por que aprender:

Reconhecer que a trava é psicológica te livra de "esperar mais features".

Conceitos-chave:

Confiança = exposição · Baixo risco repetido · 10 runs perfeitas = primeira confiança · 100 runs = segunda.

O que é:

Automações determinísticas (move arquivo X pra pasta Y) são seguras — entrada → saída fixa. Skills/agentes Claude são não-determinísticos mais poderosos mas exigem mais validação.

Por que aprender:

Confiança total em algo não-determinístico é receita pra desastre. Misture os dois.

Conceitos-chave:

ETL determinístico · LLM no meio só onde precisa · Limites claros · Saídas auditáveis.

💼 O que vender e como descobrir o que já existe

A skill de maior alavancagem do N5 não é construir do zero — é descobrir o que já foi feito.

O que é:

Em maio/2026 já tem 5.000+ skills, 800+ MCP servers, 3.000+ marketplaces de plugins. Tudo público, maioria open-source.

Por que aprender:

Reinventar é caro. Adaptar é rápido.

Conceitos-chave:

Anthropic oficial · Comunidade · Plugins (bundles) · Marketplace por verticais.

O que é:

X: busque "claude code skill" + sua vertical · Reddit r/ClaudeAI · GitHub awesome-claude-code · marketplace oficial da Anthropic · marketplaces verticalizados (devops, sales, finance).

Por que aprender:

Quem garimpa primeiro entrega cliente em 1 semana em vez de 1 mês.

Conceitos-chave:

Search-first · Validar autor · Forkar antes de adaptar · Contribuir de volta.

O que é:

Forkar · adaptar pro contexto · manter changelog claro · documentar customizações · contribuir patches de volta quando faz sentido.

Por que aprender:

Sem disciplina, você fica preso à versão antiga e perde atualizações do upstream.

Conceitos-chave:

Fork claro · Diff documentado · Rebase periódico · Contribute back.

O que é:

Revisão de PR 24/7 (R$ 8-15k/mês) · Triagem automática de backlog · Auditoria semanal de segurança/qualidade · Briefing pré-call de cliente · Relatório dominical autônomo · Monitor de competidor.

Por que aprender:

N5 não é "vendo agente de IA" — é "vendo SLA, redução de tempo, infra confiável".

Conceitos-chave:

SLA mensurável · Recurring revenue · Setup + manutenção · Posicionamento como infra.

O que é:

Habilitar rotina sem dry-run · vender autonomia em tarefa criativa · não monitorar logs · prometer SLA sem alçada · ignorar custo de tokens · entregar sem runbook.

Por que aprender:

Cada um desses transforma cliente em ex-cliente.

Conceitos-chave:

Dry-run sempre · Não autoescreva criativo · Logs visíveis · Alçada clara · Token budget · Runbook obrigatório.

O que é:

N1 chat · N2 projetos · N3 co-work · N4 Code · N5 infraestrutura. A cada nível, o "trabalho" cresce e a "babá" diminui. Próximo passo: faça a Prova (T6) honestamente. Ela revela onde você realmente está.

Por que aprender:

Quem fecha o ciclo entende a jornada como um todo, não pedaços soltos.

Conceitos-chave:

Mapa completo · Prova honesta · Plano de 90 dias por nível · Repetir.
