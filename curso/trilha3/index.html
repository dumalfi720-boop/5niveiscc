3.1~25 min

🖥 Co-work: Claude on his machine

The 7 features that transform Claude into a coworker with real access to your system.

What is it:

"Code/Co-work" tab in Claude Desktop. Run code in an isolated VM with read/write in folders that YOU authorized. You describe the result, Claude discovers the steps.

Why learn:

Kills the "I need to copy everything manually". This is where freelancers start selling automation as a service.

Key concepts:

Isolated VM · Authorized folders · Real read/write · Outcome > steps · Paid (Pro/Max/Team/Enterprise).

What is it:

Granular permission: you choose on a folder-by-folder basis what Claude can read and what he can write. Never touch anything you didn't authorize.

Why learn:

The difference between "Claude how scary" and "Claude how trustworthy" is the accuracy of the permissions.

Key concepts:

Read-only by default · Folder-by-folder · Exclusion list · Always confirm before deleting.

What is it:

Reusable workflow defined in simple markdown. Defines 1 time ("weekly customer report") and calls with 1 command. More than 100 published skills — official from Anthropic + community.

Why learn:

Skills add up: each one is a “coworker preset”. 5 well-made skills = 5x less repeated explanation.

Key concepts:

.md with instructions · Official skills (~16) · Marketplace · Works in co-work + chat + Claude Code · Be careful with the origin.

What is it:

Type /schedule in any co-work conversation and set the cadence (daily 8am, weekly Monday, etc.). Caveat: machine and desktop app must be open.

Why learn:

It's pre-N5: you get used to supervised automation before cloud routines (N5).

Key concepts:

Simple cron · Machine on · Execution history · Ideal for stand-ups, briefs, reminders.

What is it:

Pair cell phone with desktop. You send a task for traffic, the gym, the meeting. Claude runs on your desktop, you get pinged when it's finished.

Why learn:

That's when co-work stops being a tool and becomes a "real coworker" — it works for you while you're away.

Key concepts:

QR pairing · Notifications · Pocket tasks · Same session.

What is it:

Separate product from Anthropic Labs, included with Pro. You describe a deck, landing or one-pager and Claude draws it. Reads your repo/brand book and creates automatic design system.

Why learn:

Non-coder creates real frontend. Send it directly to Claude Code (N4) to put it into production.

Key concepts:

Design system extracted from the brand · Handoff bundle pro Code · Conversational editing · Free from "AI slop".

What is it:

Claude operates apps visually like a human: clicks, types, navigates menus. Useful when there is no native connector. Mac and Windows.

Why learn:

Connector breaks or does not exist? Computer Use covers. But it's slower and wrong — only use it when you need it.

Key concepts:

Last choice · Slow · Expensive in tokens · Good for legacy apps or intranets.

3.2~20 min

📂 Folder structure that makes Claude become a coworker

The difference between a reliable coworker and an unpredictable VA.

What is it:

00_about_me, 01_templates, 02_projects, 03_inputs, 04_processing, 05_outputs, 06_file. Numbered for Claude to read in order.

Why learn:

Without structure, Claude invents where to save. With structure, it follows clear and predictable rules.

Key concepts:

Numbering forces order · Folder about you · Untouchable templates · Versioned outputs.

What is it:

Say: "Read 00_about_me first. Never edit 01_templates. Always deliver in 05_outputs with timestamp. Confirm before deleting anything."

Why learn:

3-5 floor rules prevent 90% of accidents.

Key concepts:

Always/never explicit · Mandatory confirmation · Timestamp on outputs · Backup before moving in bulk.

What is it:

More than 100 skills published. 16+ Anthropic officers, rest from the community. Frontend, PDF, Excel, marketing, accounting, advertising — there’s something for everything.

Why learn:

Don't start from scratch. Search, install, customize.

Key concepts:

Official marketplace · GitHub · Known origin · Adapt before use · Plugins = skill+connector bundles.

What is it:

(1) Organize downloads (rename/categorize) · (2) Weekly report from spreadsheets · (3) Pre-meeting briefing by reading agenda+docs · (4) Deck from notes · (5) Service flow (FAQ + tickets).

Why learn:

These are the "anchor cases" of N3. Masters the 5 → sees all others as variations.

Key concepts:

Each case = repeatable recipe · Minimum permissions · Always named output · Log of what was done.

What is it:

Minimum scope permissions · protected templates · confirmation before deleting · final report ("what I did, what I didn't do, what I skipped") · start with low-risk tasks.

Why learn:

It's what separates "automation that helps" from "automation that destroys work."

Key concepts:

Principle of least privilege · Backup first · Dry-run first · Mandatory logging.

What is it:

Domain: you have 5+ skills, perform weekly rituals without typing context, deliver work to clients done in co-work. Ceiling: you need versioning, engineering rigor, or customers who would pay R$25k+.

Why learn:

Recognize the ceiling = know when to jump to Claude Code (N4).

Key concepts:

Co-work is friendly, I don't need · Rigorous engineering wants Code · Signal: "I wanted git here".

3.3~25 min

🚀 Cheat Code: the repeated task will become automation

How to find the bottleneck task of the week and sell automation as a service.

What is it:

The task you perform every week takes time, is mechanical, and has a clear input/output. These 4 criteria together = perfect candidate.

Why learn:

Automate the wrong one = wasted work. The right one = brutal ROI.

Key concepts:

Weekly recurrence · Mechanical · Clear entry · Clear exit · Non-creative.

What is it:

On N3 you can still "chat". From here on out, precision matters more than friendliness. Short text, explicit rules, fixed format.

Why learn:

Automation that accepts ambiguity = broken automation.

Key concepts:

No flourish · Input/output schema · Explicit success criteria · Fail-fast.

What is it:

You need git, parallel sessions, planning before execution, or customers paying R$25k+. Co-work doesn't cover it — Claude Code does.

Why learn:

Knowing when to go up avoids "squeezing" co-work until you get tired.

Key concepts:

Git · Worktrees · Plan mode · Sub-agents · Output styles · Premium clients.

What is it:

Give full permission · do not dry-run · do not review logs · automate creative · charge cheaply.

Why learn:

Each error destroys the customer's trust (and yours in the tool).

Key concepts:

Principle of least privilege · Dry-run first · Weekly log review · Don't automate "deciding" · Charge for the result.

What is it:

Recipe: find a client with a repeated task that costs 10h+ /week, prove it in 1 day, set it up with co-work + skills + /schedule, delivered with a simple runbook. Charge by result, not by hour.

Why learn:

It's the first level where you can sell with a clear thesis, without needing to be a dev.

Key concepts:

Clear ICP · Measurable before/after · Deliverable + runbook · Monthly maintenance · Value pricing.

What is it:

You have 5+ skills, 2+ rituals scheduled, 1 actual delivery to the client, and you are feeling the need for versioning. Ready for Claude Code.

Why learn:

Going up without this = opening terminal and crashing.

Key concepts:

Own skills · Working rituals · Real customer · Demand for git/PR/branches.
