CASE 1

📂 Organizing 3 years of Downloads (and almost erasing a contract)

Scenario

Letícia, self-employed accountant, 38, serves 22 corporate clients. ~/Downloads folder has 4,847 files: contracts, invoices, screenshots, supplier .zips, random prints. Searching for "Customer contract X 2024" takes 15 minutes. He knows it can be automated but he's afraid of Claude deleting something important.

Features:co-work activated, authorized folder (Downloads only), preferred naming models.

❌ First attempt — the near-disaster

Organizes my Downloads folder. Put the same file in a folder with the same name. Delete duplicates.

What happened:Claude began. Created folders /pdf, /docx, /xlsx, /img, /zip. Moving files. 15 minutes later Letícia noticed: a file called "contract.pdf" went to /pdf. Another "contract.pdf" (from a DIFFERENT client, different year) also went to /pdf — Claude considered it a duplicate due to the name and DELETED one.

Letícia was lucky:noticed quickly. Recovered from the Recycle Bin. But the scare was real.

Why it was ALMOST a catastrophe:

  • • Withoutdry-run first— Claude executed without showing a plan
  • • "Delete duplicates" without criteria (name? hash? size?) — Claude defaulted to name
  • • Withoutautomatic backupbefore destructive operation
  • • Withoutlogof what she was doing — it was only visible after she opened it to see

✅ Final skill with 5 ground rules

Letícia transformed learning into a reusable skill. Save in~/.claude/skills/organizar-downloads.md:

--- name: organize-downloads description: Organizes ~/Downloads into folders by category. ALWAYS with dry-run and backup. --- # NON-NEGOTIABLE ground rules 1. **Never delete.** Move, yes. Never delete. I manually delete it after reviewing. 2. **Dry-run first ALWAYS.** Before moving anything, show plan in format: - "I'm going to move X files to /folder-Y" - "I will detect Z probable duplicates (but I will not delete them — I will move them to /possible-duplicates so I can review)" And wait for my explicit OK. 3. **Backup before:** create ~/Downloads/_backup_ANTES_organizacao_YYYY-MM-DD_HHMM/ and copy 100% of the current content there BEFORE any movement. Yes, even if it temporarily doubles the space. 4. **Categories based on CONTENT, not just extension:** - "contract*" + .pdf → /contracts/AAAA/ - "NF*" or "nota_fiscal*" + .pdf → /notas_fiscais/AAAA-MM/ - Image .png/.jpg → /images/AAAA-MM/ - Others .pdf → /pdf_revisar/ - .zip → /zips_revisar/ - generic .docx → /documentos/YYYY-MM/ 5. **Mandatory log:** at the end, generate /Downloads/_log_organizacao_AAAA-MM-DD.md with: - How many files were moved by category - Complete list of "possible duplicates" (same name, different locations) for me to audit - Errors found (corrupt file, no permission, etc.) - Size before/after # How to invoke "Run the organize-downloads skill. Dry-run it first." # If I say "approve and execute" - Create backup - Move according to plan - Generates log - ASK ME before tapping any "possible duplicates"

Dry-run output:

- /contracts/2024/ → 287 files

Approve?

Leticia approved. 8 minutes later Claude delivered the log. Nothing was deleted. The 67 "duplicates" she reviewed in 20 min — 41 were actually duplicates (deleted), 26 were homonyms from different clients (preserved).

🔀 Tested variations

A — Cell phone photo folder:same structure, but category by EXIF ​​(date, GPS), not by name. Detects "selfies" vs "photographed documents" via visual pattern.
B — Work project folder:category by CUSTOMER (read the .pdf text, first 200 words to infer). Dry-run shows "97% confidence" before moving.
C — Digital signatures folder (with certificate):DO NOT MOVE. Skill detects sensitive files (.p12, .key, .pem) and skips them explicitly.
D — Saved email attachments:crosses with the sender's information (takes the file name) and organizes by contact.

⚠ Common mistakes when adapting

  • • Skip the dry run "in a hurry"— this step prevents 99% of disasters. Skip = you will learn the expensive way.
  • • Trust "delete duplicates"— duplicate by name ≠ actual duplicate. MD5 hash or byte-to-byte comparison is minimal.
  • • Do not create backup— "I have a Recycle Bin" is not a backup. Recycle bin empties, FS failure happens, "deleted by mistake 1 month ago" there's no going back.
  • • Do not generate structured log— without logging you can’t audit or revert.

CASE 2

📊 Skill "Weekly Customer Report" — copiable and versionable

Scenario

Marcos runs a micro-marketing agency (3 employees, 11 clients). Every Friday you spend 4 hours putting together 11 weekly reports (1 per client). Each one reads data from Google Ads, Meta Ads, GA4 and Notion (where they mark the week's experiments). Put everything together in an "aesthetically beautiful" PDF that the customer reads in 30 seconds.

Features:co-work, folder structure~/agencia/clientes/[cliente]/already organized, weekly exports from ads platforms.

❌ First attempt — no template

Marcos asked "generate a weekly report for client X". Claude did. But each one came out differently — one week there was a graph, another week it wasn't. Tom swayed. Metrics changed order. Customer commented: "sometimes it is complete, sometimes it seems too summarized. Is it standardized?"

Why it failed:"Weekly report" as a loose prompt produces non-deterministic output. No fixed template + no specified sources + no inclusion criteria = each run is a new decision.

✅ Complete final skill

Marcos wrote skill in~/agencia/.claude/skills/relatorio-semanal-cliente.md:

--- name: client-weekly-report description: Generates standardized weekly reports for marketing clients. Gets data from exports + Notion. PDF output in the customer folder. --- # How to invoke "Weekly-client-report skill wheel. Client: [name]. Week: [DD/MM-DD/MM]." # Prerequisites - Folder ~/agencia/clientes/[cliente]/ must exist - Exports of the week in ~/agencia/clientes/[cliente]/exports/AAAA-WW/ - google-ads.csv - meta-ads.csv - ga4.csv - Experiment notes in ~/agencia/clientes/[cliente]/notion-sync/AAAA-WW.md # Skill steps 1. **Validate inputs** - If any file is missing, ABORT and list what is missing. Don't make up numbers. 2. **Calculate weekly aggregates** - Total investment (Google + Meta) - Weighted CPL by platform - ROAS by platform - Variation vs previous week (reads folder /AAAA-WW-previous/ if it exists) 3. **Identify positive highlights and points of attention** - Highlight: biggest improvement vs previous week (any metric) - Attention: greater drop (same criteria). If none above 15% var, omit. 4. **Cross with Notion experiments** - Each active experiment in the week: associate with before/after metrics when possible - If experiment without conclusive data: mark "[inconclusive — continue next week]" 5. **Generate PDF** using ~/agencia/templates/relatorio-template.html as a base - Fixed structure: * Header: logo + client + week * KPIs on cards (3): invested, CPL, ROAS — with variation arrow * "Highlight of the week" block (green) * "Attention point" block (yellow) — only if there is * Experiment table with status * Next steps (pulls from Notion "next week" section) * Footer with generation date and contact Marcos - Save to ~/agencia/clientes/[cliente]/relatorios/AAAA-WW.pdf 6. **Generate text for pre-approved WhatsApp** - 3 summary bullets + 1 sentence "full PDF attached" - Save to ~/agencia/clientes/[cliente]/relatorios/AAAA-WW-whatsapp.txt - DOES NOT send. I copy and send. 7. **Log execution** - In ~/agencia/_logs/skill-relatorio-AAAA-WW.md - Customer, execution time, time spent, alerts # Rules - NEVER send anything alone (without Slack/Email/WhatsApp via API) - If any data seems strange (10x higher CPL, negative ROAS), MARK it with 🚨 but DO NOT change it. I validate. - PDF language: factual, without hype. "We invested R$X, generated Y leads, CPL fell by Z%." No "incredible", "extraordinary".

📤 Result

Marcos still on Friday morning, instead of 4am, spends 25 minutes:

  • • 15 min — export data from platforms (manual, still)
  • • 5 min — run skill 11 times (in parallel on the terminal)
  • • 5 min — review the 11 PDFs (any 🚨 catches attention, it validates)

PDFs go to customers at 10am. 3h35 left. Customer who complained about “non-standardization” stopped complaining — “highlight + attention” became what he reads first.

🔀 Tested variations

A — Premium client (dense monthly report):same skill, but template changes to "executive summary 1 page + 4 technical appendix". Wheel 1x/month.
B — Self-service client (self-reading report):more educational version of the text, explaining what CPL and ROAS are. Customer understands without a weekly call.
C — Skill chained with /schedule:Marcos schedules "every Friday 8am" — Claude runs automatically IF the exports are already in the folder. If missing, send an alert.
D — Emergency version:"crisis mode" for when customers call in panic — 2-day report only, no comparison, focus on the current fire.

⚠ Errors when adapting

  • • Skill without "abort on missing data"— Claude invents when given a miss. Always include "if X is missing, ABORT and let me know".
  • • Allow auto-send at start— prohibit external communication until you trust 100%. Then you relax.
  • • Skill without versioning— when you adjust (and you will), version it in git. Skill is code.
  • • Skip execution log— without logging you cannot audit recurring errors or refine.

CASE 3

⏰ Scheduled morning briefing — and the limit no one tells you

Scenario

Renata, COO at a B2B fintech, starts the day at an 8am meeting. Before the meeting, you want a 1-page briefing: dev PRs opened yesterday, critical support tickets, key metrics for overnight operation, agenda for the day. Today she spends 20 minutes opening 5 tabs and adding the manual.

Features:co-work + /schedule. Connectors: GitHub, Slack, GA4, Calendar.

❌ First attempt — scheduled and nothing appeared

Renata configured:/schedule "gerar briefing matinal" todo dia útil 6h30. Confident, he went to sleep.

7:45 am, opened the notebook:nothing. No briefing. Skill didn't run.

The painful discovery: /scheduleco-work REQUIRES machine turned on AND desktop open. Notebook closed at 11pm. No execution possible. This is the limit that separates N3 from N5 (where cloud routines run even with the machine off).

✅ Realistic adaptation on N3

Renata adapted: running manually or automatically BUT leaving the notebook on + desktop open at night. And created skill with fallback.

Skill in~/.claude/skills/briefing-matinal.md:

--- name: morning-briefing description: Morning briefing 1 page. Runs 6:30 am on weekdays IF machine is on. If I run it manually, it runs immediately. --- # Prerequisites - Active connectors: GitHub (org X), Slack (channels #support, #ops), GA4 (owned Y), Calendar (personal) - Machine turned on + desktop open if /schedule # Steps 1. **GitHub (last 12h)** - PRs opened yesterday after 6pm - PRs with ≥2 days without review - Issues marked as [urgent] 2. **Slack (overnight, 6pm yesterday → now)** - Messages in #support with tag :rotating_light: - Threads in #ops with more than 5 responses - Direct mentions to @renata 3. **GA4 (last 24h)** - Sessions, conversions, errors 500+ (if applicable) - Compare with average of the last 7 days - Automatic flag if variation > 25% 4. **Calendar (today)** - Each meeting with: time, title, participants, link 5. **Compose briefing** - Fixed structure (template in ~/templates/briefing-matinal.md): - 🔥 Attention NOW (up to 3 items, only if really urgent) - 📊 Overnight metrics (4 numbers + variation) - 📋 Pending decisions (PRs without review, open threads) - 📅 Agenda of the day (5 meetings max, ordered) - 🧘 "Today you can focus on..." (1 sentence with derived priority) 6. **Deliver** - Save to ~/briefings/YYYY-MM-DD.md - Open automatically in the editor (open command) - DO NOT send Slack/email — Renata reads it first # Rules - If any connector fails, generate a briefing with what you can achieve + list "sources that failed" - "Attention NOW" only with concrete facts. Without "everything seems fine" in the void. - Maximum 1 page in A4. If it exceeds, cut it. # Fallback if /schedule does not run (machine off): "Renata, run 'briefing-morning NOW' when you open your notebook."

🔀 Tested variations

A — Pre-call customer briefing:trigger by Calendar event 30min before. Generates briefing focused on the specific client (history, decisions, pending issues).
B — Sunday weekly briefing:instead of a diary, it summarizes the entire week. Renata wheels manual before Monday's planning meeting.
C — "Crisis mode":runs on the fly, ignores fixed structure, focuses only on the current incident with timeline.
D — Pro team version:same structure, but filtered (without sensitive details), generates a version to post on #ops every day at 8:45 am.

⚠ Errors when adapting

  • • Forgetting that N3's /schedule needs the machine turned on— will catch you soon. For routine without a machine, wait for N5.
  • • Allow automatic sending to Slack/email from the start— read first for 2 weeks before enabling.
  • • Trying to pull from 8 connectors at the same time— start with 2-3, expand later. More connectors = more noise.
  • • Briefing too long— if it’s more than 1 page, no one reads it. Skill MUST force cut.

🧠 The N3 standard behind the 3 cases

When Claude operates his machine, the ingredients change. It's no longer "paper + context + format". AND:

  1. 1. Always dry-run before the first run— Claude describes plan, wait explicit OK. Did you skip it once? He learned the expensive way.
  2. 2. Automatic backup before destructive operation— independent of Recycle Bin/Trash. Backup = snapshot that you control.
  3. 3. Permission to abort with missing source— "if X is missing, ABORT and let me know" kills 80% of hallucinations in skills.
  4. 4. Mandatory structured logging— without logging you can’t audit or refine. Skill without log = black box.
  5. 5. Prohibit automatic external communication until you trust— Claude generates, you command. When confidence matures (50+ clean runs), then relax.

The 5 ingredients of N1 ("role + context + format + restriction + output") are still valid. These 5 from N3 are ADDITIONS, not replacements.
